# career-ops 本地控制台

给 career-ops 做的一个本地网页界面。项目原本只能靠 AI 命令行工具驱动（要敲斜杠命令、看终端输出、手改 YAML），这个界面把数据可视化，并把高频操作变成点按钮。

**它能自己拉起 AI 做事。** 「评估岗位」页可以直接粘贴 JD 出分数和报告（内部调用 AI CLI）；
但**简历改写、面试准备这类多轮对话的操作仍然要命令行**——控制台的长处是
**看状态、改数据、跑脚本、导文件**，以及「一句话就能完成、不需要来回聊」的 AI 任务。

## 快速开始

双击项目根目录的 `start-ui.cmd`，浏览器会自动打开 `http://127.0.0.1:7317`。

或者手动启动：

```bash
node ui/server.mjs            # 默认 7317 端口
node ui/server.mjs --port 8080
```

停止：在终端窗口按 `Ctrl+C`。

## 导航结构

顶部导航条分**五栏**（总览 / 做简历 / 评岗位 / 分析 / 系统），共九个入口，越靠左越常用。
**一级只放这五栏**，栏目里的功能项收进下拉面板——这样一级的目标数不会随着功能增加而膨胀，
「系统」也正好装下那些一个月点一次的琐碎入口：

| 一级栏目 | 下拉里的入口 | 干什么 |
|---|---|---|
| **总览** | （单项，点了直接走） | 初始化状态、关键指标（岗位数、平均分）、转化漏斗、环境检查、常用命令快捷按钮 |
| **做简历** | 我的简历 | 表单化编辑简历，实时预览 Markdown，一键生成 PDF；顶部可让 **AI 优化简历**（给问题清单 + 可写回的改写稿） |
| | 简历工具 | 简历相关脚本：**中文简历自检**、**生成面试准备包**、事实核验、ATS 兼容检查、JD 相似度、转 PDF、生成求职信 |
| **评岗位** | 评估岗位 | **直接在页面里做评估**——粘链接或 JD，服务端拉起 AI 出报告；可一次批量初筛多个岗位（支持导入 .docx/.xlsx/.csv/.txt） |
| | 评估报告 | 浏览 `reports/` 下的 A–H 评估报告（含 Markdown 渲染）；每张卡可删除（连带清掉引用它的台账行，删前进 `data/trash/`） |
| **分析** | 面试备考建议 | 拿一份报告的「岗位要求 + 能力评估结论」跟你的简历做差距对比，输出要补的知识点（带优先级与掌握程度）、能写进简历的实践项目、以及具体到能搜到的学习资源；支持复制全文与导出 .md |
| **系统** | 求职配置 | 编辑 `config/profile.yml` 常用字段 + 岗位源 `portals.yml` |
| | 全部脚本 | 一键运行全部 43 个本地脚本，零 token、不花钱 |
| | 自动投递 | BOSS 直聘批量打招呼。**默认只出计划，一个字都不发**；真实发送要过一次确认框 + 服务端二次校验，另有每日上限、随机间隔、台账去重、遇滑块即停四道闸门 |
| | 使用帮助 | 命令速查、CLI 选择、文件分层说明。**排在最后一位**——它是"出事了才找"的入口 |

面试备考建议 / 评估报告两项在导航条上会显示实时数量徽标。

**交互**：鼠标悬停、键盘聚焦、点击都能展开下拉；同时只会开一栏，点栏目外或按 Esc 收起
（`aria-expanded` 由 JS 同步，展开本身是纯 CSS）。**单项栏目不出下拉**——总览、分析点了直接走。

**为什么这样分组：** 两个「干活的」页面（全部脚本 / 简历工具）共用同一套工具面板组件，
只是喂给它的脚本分组不同——`null`（全部）、`['cv']`（简历）。
这样在常用场景里（改简历时就只看到简历脚本）不用在一堆脚本里翻找，
需要时又能到「全部脚本」页一览无余。

**「系统」为什么是杂物抽屉：** 求职配置 / 全部脚本 / 自动投递 / 使用帮助 这四个入口都不属于任何
一条功能流程，各占一个一级座位既浪费横向空间、又打散了主流程的节奏。收进一栏之后，
一级横栏永远是「总览 → 做简历 → 评岗位 → 分析」这条主线 + 一个低频的「系统」。
**「使用帮助」仍在最末位**：桌面它是「系统」下拉的最后一项，窄屏抽屉里钉在最底部。

> **新增「自动投递」**（2026-09-26）：入口在「系统」栏、排在「使用帮助」之前，
> 于是**功能项 9 → 10、一级栏仍是 5 栏**（加第 6 栏会让 1279 / 1119 两档窄屏把入口挤没）。

> 设计，并有专门的自检 `ui/check-auto-apply.mjs` 守着（只跑 dry-run，绝不在自检里真发）。

> **顶部导航改为五栏下拉结构**（2026-09-22 第四版）：一级从 9 个平铺入口收成 5 栏，入口数不变。

## 在页面里直接评估（`/api/eval`）

这是控制台唯一会**主动拉起 AI** 的地方。它做的事和你在终端里说「评估这个岗位」完全相同。

### 两阶段设计（由实测速度决定）

| 阶段 | `phase` | 读哪些规则 | 耗时 | 产出 |
|---|---|---|---|---|
| 初筛 | `triage` | `_brief.md` + `_profile.md` | 约 25–35 秒 | 分数 / 结论 / 档位 / 一句话理由 |
| 完整 | `full` | 上面 5 份 + 按需 grep `oferta.md` | 十分钟以上 | `reports/*.md` + 台账更新 |

完整评估要读约 17.6 万字符的规则（光 `modes/oferta.md` 就 8 万字符），
再写一份 A–H 结构化报告、更新台账——这在交互式页面上等太久。
所以默认只跑初筛给即时反馈，用户想深入时再点「生成完整报告」。

分数门槛是 **3.0**（`config/profile.yml → pipeline.triage_threshold`）。
初筛过门槛才把「生成完整报告」按钮露出来，避免用户对着低分岗位白等十分钟。

**服务端流程：**

1. `/api/eval` 校验入参（链接格式、JD 长度 ≤ 3 万字符、至少填一个）
2. `findAiCli()` 按优先级探测 AI 命令行：`CAREER_OPS_AI_CLI` 环境变量 →
   项目本地 `node_modules` → 各 CLI 的常见全局安装位置（CodeBuddy / Claude Code / opencode / Gemini）
3. 按 `phase` 拼装 prompt：**显式要求 AI 读哪些规则文件**，再按约定输出
4. `resolveEngine()` 决定这一次谁去跑（见下一节），再由 `runAi()` 统一封装 ——
   走 CLI 时以无头模式跑 `codebuddy -p <prompt> --add-dir <ROOT> --port <空闲端口> --output-format text`，
   走本地模型时调 Ollama 的 `/api/chat`。两条路的返回值同形，所以这一步以上没有分支
5. 解析 AI 输出（初筛阶段提取结构化字段），把原文与解析结果一起返回前端

### AI 引擎：CodeBuddy 或 本机 Ollama

「评估岗位」页顶部有张「AI 引擎」卡片，可以随时切换；选择落盘在 `data/ai-engine.json`
（放 `data/` 而不是 `config/profile.yml`：它是跟本机环境绑定的设置，且 `data/*` 已被
`.gitignore` 排除，换机时不会把「我这台机器选了哪个引擎」带走）。

| 引擎 | 能做什么 | 不能做什么 |
|---|---|---|
| `cli`（CodeBuddy） | 读规则、写 `reports/` 与台账，**完整评估只能它来** | 要联网、消耗 CLI 额度 |
| `ollama`（本机开源模型） | 初筛、简历优化；离线、零成本、简历原文不出本机 | 读不了项目文件、写不了盘 |
| `auto`（默认） | 优先 CLI；CLI 不可用时退回本地模型 | —— |

决策口径在 `ui/ai-engine.mjs`（纯函数，`ui/check-ai-engine.mjs` 直接测）。
两条容易踩的线：

- **显式选择不会被静默兜底。** 选了本地模型而服务没起，不会偷偷改用 CLI ——
  那会让用户以为自己在用免费模型，实际每次都在烧 CLI 额度。
- **「完整评估 + 本地模型」由服务端 409 挡住**，并在页面上提前禁用。
  本地模型看不到项目文件、也写不了盘，让它跑只会得到一段漂亮但落不了盘的输出。

**为什么 prompt 要写死那些文件路径：** 不写的话 AI 可能直接凭常识给个分数，
产出和终端里跑的不一致。写死之后，页面里出的报告与终端里跑的是同一份。

### CLI 的三个坑（都会表现为「跑完了但没结果」）

**坑 1：端口冲突。**
CLI 用 `--port` 起一个自己的本地服务。端口被占时它不一定报 `EADDRINUSE`，
而是**退出码 0 + 输出为空**，stderr 里留一句**误导性**的报错——实测撞到过
`Authentication required. Please use /login`，害人先去查登录态。
所以**不写死端口**：每次调用用 `net.createServer().listen(0)` 向系统现要一个空闲端口。
（`CAREER_OPS_AI_PORT` 可覆盖，主要用于调试。）

**坑 2：并发。**
CLI 很重。页面上双击按钮、或同时开着两个标签页，两个进程互相抢资源，
表现就是「随机某一次空返回」。`runAi()` 用 `withAiLock()` 串行化，排队比并行靠谱。

**坑 3：无头模式的权限拦截（完整评估跑不出来的真正原因）。**
`-p`（无头）模式下 CLI 默认把 **Write / Bash / PowerShell 全部拦掉**。
表现极具迷惑性：退出码 0、输出正常、AI 还礼貌地告诉你它写不了文件——

> 「评估已完成，但当前会话为非交互模式，Write / Bash 全被权限拦截，
> 无法创建 `reports/` 报告文件……请用 `codebuddy -p -y` 重跑」

也就是说规则读了一万七千字、报告一个字节也没落盘，用户等十分钟拿到一段「我写不了」。
**完整评估必须加 `-y`（`--dangerously-skip-permissions`）**，否则功能等于不存在。
只给 `full` 加、初筛不加——初筛明确不写文件，把影响面压到最小。
（`CAREER_OPS_AI_NO_BYPASS=1` 可关掉这个行为。）

**静默失败重试：** `runAi()` 检测「退出码 0 + 未超时 + 输出为空」这个指纹，
换端口自动重试一次；两次都空才把 stderr 交给用户，并标记 `retried: true`。

**别信 AI 的自述，要看文件。** 完整评估跑完前后各快照一次 `reports/` 目录，
用「有没有文件新增或被重写」判定成败（同一天重跑同名岗位走「重写」分支，
所以比对的是 mtime 而不只是文件名）。没落盘就把 `ok` 置为 false 并给出提示——
否则会出现「页面显示成功、文件夹里什么都没有」这种最难排查的假成功。

### 输出解析：按结构解析，不靠标签名

模型输出的**措辞完全不受控**。同一句 prompt 实测跑出过四套档位标签：
`分级` / `评级` / `等级` / `层级`；分数是 `评分` 或 `分数`，
理由是 `原因` / `理由` / `评估理由`。偶尔又严格照 prompt 的英文标签回
（`SCORE/VERDICT/TIER/WHY`）。穷举同义词是打地鼠——加一个又会冒新的。

所以 `eval-parse.mjs` 改成利用 prompt 要求的**固定四行结构**，
用内容特征定位，标签名只作第一层兜底：

| 字段 | 定位方式（按优先级） |
|---|---|
| `score` | 全局正则 `(\d(?:\.\d)?)\s*/\s*5`，不依赖行序 |
| `verdict` | 标签 → 内容含 `通过/不通过/PASS/FAIL`；**判定否定优先** |
| `tier` | 标签 → 档位词表（`强匹配/值得投递/补投位/不建议`）→ 最短的那条 |
| `why` | 标签 → 最长的那条 |

**否定优先是必须的**：先匹配 `通过` 的话，「不通过」会被判成 PASS，直接判反。

**还要剥 markdown 装饰**：模型常输出 `**评分：** 4.4/5`，
不剥的话标签变成 `**评分`、值变成 `** 4.4/5`，
按标签匹配全部落空——分数还侥幸能靠正则捞回来，档位就静默丢了。

解析单独成模块 + 配回归测试，是因为它坏掉的方式是**静默降级**：
分数正常显示、档位和理由悄悄消失，不抛错、控制台也干净，手点一遍发现不了。

```bash
node ui/check-eval-parse.mjs     # 9 个用例，标签全部取自实跑输出
```

**安全边界：** 前端只能传「链接」「JD 正文」「阶段」三个值，**不能指定 prompt 或命令**。
prompt 完全由服务端拼装。JD 正文长度有上限。

### 评估会话：切页不丢结果（`S.evalSession`）

`route()` 每次切页都会 `view.innerHTML = viewSkeleton(id)` 把整个视图重建。评估结果直接写在 DOM 上的话，用户切去台账再回来会发现**分数、结论、日志全没了**；更糟的是**请求还在飞的时候切走**——回调会去写已经 detach 的节点，`$('#evState')` 拿到 `null`，直接抛 `Cannot set properties of null`。

所以评估页的状态不放 DOM，放会话：

| | 内容 |
|---|---|
| `S.evalSession` | 输入框内容、运行态与忙碌按钮、状态徽标、提示、日志、结果 HTML、按钮形态、`triageScore` |
| `paintEval()` | **唯一**的「会话 → DOM」出口；当前不在评估页时直接返回 |
| 其余代码 | 一律「改会话 → `paintEval()`」，不再直接写 `#evResult` 这类节点 |

于是三件事同时成立：切走再切回，结果完整还原；请求在别的页面上跑完时只更新会话，界面等切回来再补；点「清空 / 再评估一个」之后，飞在半路的旧请求回来不会把结果重新写回页面（靠 `runId` 代次判定）。

两处必须留意的细节：

- **输入框**要用 `input` 事件写回会话（`pullEvalInputs`），paint 只做单向回填——否则打字打到一半会被会话里的旧值覆盖。
- **结果区里的按钮**（`[data-open-report]`）是 `innerHTML` 恢复出来的，逐个 `addEventListener` 切页后就失效了，所以绑在 `#evResult` 上做**事件委托**。
- 视图已删除但 hash 还停在上面的情况（旧书签、浏览器后退）由 `route()` 兜底重定向到总览，否则会白屏。

回归入口：`node ui/check-eval-flow.mjs` 的第 8–10 步专门守这条线。

## 简历编辑器：表单草稿优先（`S.cvDraft`）

简历页的表单**不是**每次渲染都从服务端重新载入的。规则是：

- 首次进入（或没有未保存改动）→ 用 `/api/cv` 返回的 `form` 作为工作副本，存进 `S.cvDraft`
- 有未保存改动（`S.cvDirty`）→ **一律以本地草稿为准**，服务端那份不再覆盖它

**为什么必须这样：** 原先 `rerender()` 会重新拉一次 `/api/cv` 再整体覆盖表单，于是

```
点「+ 添加证书」→ 新条目 push 进数组 → 重新拉取 → 服务端那份还是空数组 → 覆盖 → 条目消失
```

表现就是「点了添加没反应」（教育背景 / 证书 / 荣誉奖项 / 工作经历全中招）。
更严重的是同一个覆盖会**把用户已经敲进表单的所有文字一起冲掉** ——
只要点一次上移 / 下移 / 删除就会触发。

**配套的三件事：**

| 事项 | 做法 |
|---|---|
| 重画不滚回顶部 | `route({ keepScroll: true })`。「+ 添加」按钮在页面下方，滚回顶部会被当成「点了没反应」 |
| 完整度怎么算 | 走只读的 `POST /api/cv/preview`（只算不落盘）。规则只在 `cv-model.mjs` 一处，不在前端重复实现 |
| 未保存怎么提醒 | 保存按钮文字加「（有未保存改动）」+ `beforeunload` 拦截。**页内切换不拦** —— 草稿在内存里，换个页面再回来改动还在 |

**顺带修掉的一处重复逻辑：** 横幅原本在「没有缺失项」时把 `100%` 写死。
当前算法下 `缺失为空 ⟺ 百分比 100`，所以碰巧不出错；但那是把百分比规则抄了第二份，
将来调整权重就会静默说错话。现在两个分支都用 `comp.percent`。

## AI 优化简历（`/api/cv/optimize`）

「我的简历」页顶部有个面板：点一下就让 AI 通读简历，给出一份**问题清单**和一份**改写稿**。
粘一份目标岗位 JD 就按那个岗位定向优化，留空则按 `config/profile.yml` 里的目标方向做通用优化。

**为什么是两步，而不是让 AI 直接改 cv.md：** `cv.md` 是全系统的事实来源，所有评估都读它。
让模型在无人确认的情况下覆盖它，一次幻觉就可能把「参与过」改写成编造的经历和数字。
所以这里强制拆开：

| 接口 | 干什么 | 会不会写文件 |
|---|---|---|
| `POST /api/cv/optimize` | 读 `cv.md` + `profile.yml` + `modes/_profile.md`（可选 JD），只回文本 | **不会**。`runAi` 刻意不带 `bypass`，写权限是关的 |
| `POST /api/cv/optimize/apply` | 把用户确认过的改写稿写回 `cv.md` | 会。**先备份**到 `data/cv.backup-<时间戳>.md` |

**写回那一步有三个必须做的动作：**

1. **先备份**，与 `/api/cv` 保存共用同一套命名，用户能在 `data/` 下找到。
2. **先体检**：`auditCvMarkdown(改写稿)` 逐节核对，只要有一节「有内容却解析不出
   条目」就返回 422 并且**一个字节都不写**。因为 `apply` 之后表单是由
   `markdownToCv(改写稿)` 重建的，解析不出来的那节在表单里就是空的 ——
   用户下一次点保存，它会从 `cv.md` 里被彻底删掉。
3. **重建 `data/cv-form.json`**。`getCv()` 的优先级是「有表单缓存就用它」，
   只改 `cv.md` 的话简历编辑器会继续显示旧内容，用户下次点保存又把旧内容写回去 ——
   改写稿当场作废，而且看起来像「优化没生效」。所以 `apply` 顺手把新 Markdown
   反解成表单存下来（和 `/api/cv/import` 同一条路）。

响应里还会带一个 `warnings`：相对写回前少了哪些章节、有哪些章节名解析器不认识、
完整度是否下降。它不拦写回，但**必须在页面上显示出来** —— 静默变少是最难发现的失败。

## cv.md 的解析契约（关系到「会不会丢内容」）

`cvToMarkdown` 是**全量重建**，所以 `markdownToCv` 读不懂的内容，保存一次就没了，
且不报错。三道防线：

| 防线 | 在哪 | 干什么 |
|---|---|---|
| 别名穷举 + 后缀兜底 | `cv-model.mjs` 的 `SECTION_ALIASES` / `sectionKeyOf()` | `实习经历`、`荣誉奖项`、`获奖情况`… 都能落到正确的 section |
| 排版降级 | `cv-model.mjs` 的 `sectionBlocks()` | 没有 `###` 小标题、整节只有列表项，也能解析出条目（结构可退化，内容不许丢） |
| 写盘门禁 | `auditCvMarkdown()` + 两个接口 | `/api/cv` 保存会整节消失 → 409 + 章节清单，前端弹确认后带 `force:true` 重发；`apply` 解析不出条目 → 422 拒写 |

`ui/DESIGN.md` 的「cv.md 的『解析 ↔ 重建』契约」一节有完整说明，回归在
`ui/check-cv-optimize.mjs` 的 A2 段与 B6/B7。

**输出协议**（解析在 `cv-optimize-parse.mjs`，单独成模块配回归测试）：

```
SUMMARY: <一句话总评>

### 问题清单
1. [高] 问题标题 —— 说明与改法
...

### 改写稿
```markdown
<整份简历，可直接覆盖 cv.md>
```
```

解析只认结构、不认标签名：小标题被加粗（`#### **问题清单**`）、列表项用 `1、`、
围栏忘了闭合、干脆没写「改写稿」小标题（那就取全文最长的代码块）都能认出来。
认不出来时**不猜** —— `draft` 明确返回空串并附一句 `parseError`，
页面显示「没解析出改写稿」+ AI 原始输出，而不是把问题清单当简历写回文件。

**与评估会话同一套会话规则**：状态放 `S.cvOpt`，`paintCvOpt()` 是唯一的 DOM 出口。
AI 要跑一两分钟，用户切去别的页面是常态；写在 DOM 上的结果会丢，
而且回调还会去写已经 detach 的节点。

## 删除记录（可恢复，`/api/tracker/delete` + `/api/report/delete`）

评估报告每张卡都有「删除」按钮（台账页撤下后，**单行删除改走 CLI**：
`node tracker.mjs delete --num N`，`/api/tracker/delete` 接口仍然保留）。两处都遵守一条规矩：
**先把「会动到什么」讲清楚，再动手；动之前原件先进 `data/trash/`。**

| 删什么 | 结果 |
|---|---|
| 台账某一行 | 该行从 `applications.md` 移除。删前把**整份台账**快照到 `data/trash/<时间戳>-applications.md`（台账是一个文件、行是它的一部分，没法只搬一行走） |
| 一份评估报告 | 报告本体移到 `data/trash/<时间戳>-report-<原名>.md`，**同时删掉台账里引用它的那些行**，不留点不开的死链 |

删除动作全部落在回收目录，界面上立刻消失、文件却还在；`data/trash/README.md`
写明了几种恢复办法。**目录不会自动清理**，攒着不影响功能，确认不要了手工清空。

几个刻意的决定：

- **台账的删行不自己改文件**，而是调官方 `tracker.mjs delete --num N` ——
  它带跨进程锁、原子替换和索引重建，手写正则去删行迟早会把表格写坏。
- 报告的删**会连带删台账行**，所以确认框里必须逐行点名（`第7行 华为…`）。
  否则「删一份报告顺手删掉一行投递记录」就是一次静默的数据损失。
- 报告卡整体是「打开报告」，删除按钮要 `stopPropagation()`；卡片的键盘处理器
  还要加 `e.target !== el` 判断，不然焦点在删除按钮上按 Enter 会「删完顺手把报告打开」。
- 文件名白名单（`REPORT_NAME_RE`）由读取与删除**共用**，避免两处规则漂移；
  路径分隔符一律不收，`../cv.md` 会被收敛成 `cv.md` 并在 `reports/` 里找不到。

回归：`node ui/check-delete.mjs`（A 参数校验 / B 真删台账行 / C 真删报告 /
D 前端打桩流程；B、C 会临时往台账追加自检行 998、999 并在 `finally` 里还原，
还额外把原始台账写一份到系统临时目录当第二道保险）。
**注意 D 段有一半会跳过**：「台账行内删除按钮」随台账页一起撤下后没有宿主页面，
脚本会扫一遍所有视图找 `#tBody [data-delrow]`，找不到就整段跳过并写明是已知缺口
（不是通过）。接口层的 A/B 段照跑不误，所以「删除可恢复 + 连带删行」这条契约并没有失去守护。

## 面试备考建议（`/api/prep/list` + `/api/prep/generate`）

评估报告回答的是「这个岗位值不值得投」，但它没告诉你**差的那几块怎么补**。
这一页把报告里的**岗位要求 + 能力评估结论**跟 `cv.md` 里的经历技能做差距对比，
输出三部分：

1. **需要学习与补充的知识点** —— 每条带优先级（P0 必须掌握 / P1 重点补强 / P2 加分项）
   与掌握程度要求（了解概念 / 能上手用 / 能讲原理）
2. **可用来补全简历的实践项目建议** —— 项目目标 + 技术要点 + 对岗位的价值 + 工作量估算
3. **学习资源清单** —— 按知识点分组，标出「视频课程 / 书籍 / 官方文档 / 练习题库」

口径单点在 `ui/prep-model.mjs`（零依赖，浏览器与 Node 共用）。
界面在「分析 → 面试备考建议」；每份报告详情页顶部也有一个「生成备考建议」按钮，
点进去会自动带上当前这份岗位。

### 三个刻意的设计决定

**① 岗位要求 ≠ 岗位职责，两者必须分开。**
JD 前半段通常是「参与 X 系统的开发与维护」这类**职责** —— 它说明这份工作让你干什么，
**不告诉你该学什么**。早期版本把两者混在一个 `requirements` 里，结果「技术要点」
变成「在岗位要求的技术栈里选型：参与公司核心业务系统的后端设计与迭代，保障系统高可用…」，
等于把 JD 抄了一遍。现在 JD 归档原文按小标题切成 `reqs` / `duties` 两类块，
职责只在实在取不到要求（< 3 条）时兜底。

**② 报告解析要认多种写法，不能只认一种。**
实测同一个模板产出了六种差距清单形状：`**Gaps:**` 短横线清单 / `Gaps flagged:` /
`### 差距清单` 表格 / B) 节的「要求 | 匹配」表 / 没有差距小节 / 干脆是残报告。
只认第一种的话，「解析出 0 条差距」会被误判成「这个岗位没短板」，然后页面显示一堆
空洞建议 —— 比报错更糟。所以按可靠性从高到低全认，最后一道网是**拿 JD 要求与
`cv.md` 现推**（`deriveGapsFromJd`）。

**③ 差距项落不成项目的东西要挑出来。**
「ACM / 蓝桥杯 / 天梯赛」是奖项、「开源项目贡献经历」是履历、「2027 届本科」是门槛 ——
这些写进「技术要点」会变成「技术要点：ACM / 蓝桥杯」，读起来就不对。
`pickBuildableNames()` 两档过滤：硬档看报告原句（名字已收敛，只看名字会漏「竞赛」），
软档只看名字（「…相关项目或**实习**经历」里的「实习」只是话术，按原句判会误杀）。

### AI 生成 + 本地兜底

优先用配置好的 AI 引擎；AI 不可用、或返回的三段不完整时，自动降级到
`buildLocalFallback()` 的纯规则版（零 token、秒级），并在页面上**明确标注**
这一版是怎么来的 —— 不能悄悄换一套结论。

判定「AI 输出可用」交给 `prepOutputUsable()`：知识点 ≥ 3 条、项目 ≥ 1 个、资源 ≥ 1 条。
不全就让 `prepUnusableReason()` 说清缺哪一段，然后走兜底。

### 数据缺失时的表现

- 下拉里**灰着但看得见**：不能生成的岗位直接 `disabled`，选项文字后面加「— 数据不足」，
  选中时现场写明为什么（取自服务端的 `blockHint`）
- 生成按钮对这类岗位直接置灰
- 服务端兜底：`/api/prep/generate` 返回 400 + `{ error, missing: [...] }`，
  页面把 `missing` 摊成清单，而不是只显示一句「生成失败」
- `cv.md` 为空是**全局**问题（每个岗位都报同一句），所以在工具条下面统一说一次

### 复制与导出

结果出来后顶部出现「复制全文」和「导出 .md」。
复制走的是 `toPlainText()` —— **剥掉 Markdown 记号**再进剪贴板（`## 一、需要学习…`
变成 `一、需要学习…`），粘到聊天窗口里不会是一堆 `#`。
导出文件名由 `prepFileName()` 从报告标题反推（`星海科技 — 后端开发工程师（Java 方向）`
→ `面试备考建议-星海科技 — 后端开发工程师（Java 方向）.md`），标题缺失才退回文件名。
文件名里的 `\ / : * ? " < > |` 一律换成 `-`，长度截到 60 字，避免写盘时非法。

回归：`node ui/check-prep.mjs`（131 条断言）。分两段：§0 是纯函数段 —— 直接喂真实报告
与仿真 AI 输出，**不开浏览器、不联网、不依赖 Ollama**；§1–§6 是页面段，全流程真点一遍。
生成一律选「本地规则版」，所以秒级、零 token。

## 国内求职阶段：显示用中文，存储用英文

上游的投递状态是按欧美节奏设计的：`Applied → Responded → Interview → Offer`。
粒度太粗——看不出候选人卡在简历筛选、笔试测评，还是卡在复试。
所以状态表扩了 7 个国内阶段。**这套阶段不绑定校招**，校招 / 社招 / 实习通用：

```
已投递 → 简历筛选 → 笔试 / 测评 → 初试 → 复试 → 终面 → 谈薪 / HR 沟通 → 正式 Offer
                                                        ↘ 无回应（超过 3 周可按此归档）
```

**关键设计：显示名与存储值分离。**

| | 值 |
|---|---|
| 界面显示（下拉、徽标、筛选、弹窗「当前」） | 中文：简历筛选 / 初试 / 复试 / 终面 / 谈薪 / HR 沟通 |
| 写进 `data/applications.md` 的 Status 列 | 规范英文：`Resume Screening` / `Interview 1` / `Interview 2` / `Final Interview` / `Salary Negotiation` |
| 前端发给 `/api/tracker/status` 的 `state` | 英文 id：`screening` / `first_interview` / `second_interview` / `final_interview` / `salary_negotiation` |

为什么不能直接写中文进台账：`verify-pipeline.mjs` 会校验「所有状态都是规范状态」，
`normalize-statuses.mjs` 会按状态表归一化，`funnel-velocity.mjs` 会拿 `status-log.tsv`
里的 `from` 单元格去状态表里查。写中文进去，这三处会同时报错或静默丢数据。

中文靠 `templates/states.yml` 每个状态上的 `cn:` 字段提供，`/api/states` 把它透给前端。
同一个状态还带**中文别名**，既有新写法的（`简历筛选` / `初试` / `复试` / `终面` / `谈薪`），
也有被它吸收的旧写法的（`一面` / `二面` / `在线测评` / `HR面`），
所以即使有人在文件里手写了中文，归一化也能认出来。

**这个扩展写在系统层文件里，需要能重放。** `templates/states.yml` 和 `stats.mjs`
是系统层，`node update-system.mjs` 会把它们还原成上游版本。本地化的事实来源是
`tools/apply-cn-localize.mjs`：

```bash
node tools/apply-cn-localize.mjs            # 打补丁（幂等，可反复跑）
node tools/apply-cn-localize.mjs --check    # 只检查不写
node tools/apply-cn-localize.mjs --revert   # 还原成上游版本
```

系统更新之后重跑一次即可。脚本会在改动前把原件备份到 `data/_cn-localize/`，
并且**只删自己写的说明段**（用 `CN-LOCALIZE:BEGIN/END` 哨兵标记）——
早先的实现靠「从说明开头删到文件末尾」替换，而上游文件里 `states:` 恰好排在
说明之后，于是第一次打补丁就把 `states:` 一起删了，文件直接变成非法 YAML。

**漏斗分桶（`stats.mjs`）：** 新阶段不新增层级，只归入已有四个桶——
测评/笔试 → 已回应，一面/二面/HR 面 → 进入面试，意向书 OC → 视为拿到 Offer。
「无回应」计入 `everApplied`（和 `Rejected` 同理：它证明岗位确实投出去了；
不这样算，被公司晾着的岗位不进分母，回应率会虚高）。
上游 9 个状态的计算结果**一字未改**。

|---|---|---|

| 分析 | 8 | 漏斗统计、被拒规律、技能缺口、周报、黄金样本评估 |

**需要填参数的脚本会自动展开表单**（8 个脚本共 10 个输入框）。参数在前后端做双重校验：

- 前端：`data-pattern` 正则，不匹配就把输入框标红并拒绝提交（不发请求）
- 后端：`/api/run` 用同一份正则再校验一遍，并把值作为 `spawn` 的**数组元素**传入——
  全程不经过 shell，所以没有命令注入面

**加一个脚本：** 在 `server.mjs` 的 `SCRIPTS` 里加一条即可。如果它需要参数，
补一个 `params` 数组，每项形如
`{ name, label, type, required, pattern, hint, default, flag, multi }`。
`pattern` 是防注入的关键防线，**必须写**。

## 界面设计规范

界面遵循一套设计令牌（design token）驱动的规范，规则写在 **`ui/DESIGN.md`**，包括配色与间距令牌、信息层级、组件规范、交互反馈、无障碍要求、响应式断点与可维护性约束。

想直接看组件长什么样，启动控制台后打开 **`http://127.0.0.1:7317/design-system.html`**——这是一个引用同一份 `style.css` 的活组件画廊，改了样式就能立刻对照检查。

**视觉风格：** 新拟态（Neumorphism）· 冷调清透。中性冷白画布 `#f2f4f6`，元素与背景同色同材质，靠一对双向柔光（暗侧 `#d6dce3` 右下 + 亮侧 `#ffffff` 左上）表现"从背景里凸起"或"压成凹陷"；主色是冷松绿 `#2f6b52`，琥珀 `#c98a3c` 只做"进行中 / 待办"的强调。卡片**不加描边**——边界完全由阴影交代。全部色值/间距/圆角/阴影都取自 `style.css` 的 `:root`，组件里不硬编码。

**响应式：** ≥1024px 为**顶部导航横栏**（一条常驻横栏：品牌徽标居左、**5 个一级栏目**居中、项目目录胶囊居右；栏目悬停/聚焦/点击展开下拉）；<1024px 导航栏收成左侧抽屉，由左上角汉堡按钮唤出（支持 Esc 关闭、点击遮罩关闭、视口变宽自动复位）。窗口变窄时**依次收起装饰**（先目录胶囊 → 再品牌文字 → 再栏目图标），而不是用 `overflow` 裁掉入口——1024px 下 5 栏仍然全部可见。断点 1560 / 1439 / 1279 / 1119 / 1023 / 767 / 519px。

**交互反馈：** 加载用骨架屏（每个视图形状不同），空数据有出口按钮，出错有重试按钮，长任务按钮进入忙碌态，结果用 toast 提示。所有反馈区域都是 live region，读屏可感知。

**无障碍：** 提供跳转链接、`aria-current` 标记当前导航、下拉触发器带 `aria-haspopup` / `aria-expanded`、模态框焦点锁定与 Esc 关闭、`:focus-visible` 焦点环（2px `#2f6b52`）、`prefers-reduced-motion` 与 `forced-colors` 降级。正文对比度 9.21:1、次要文字 5.96:1、辅助文字 4.91:1，主按钮白字 6.28:1，全部达到 WCAG AA。**注意 `--accent-2`(`#6f9e85`) 只有 2.8:1，只能用于图形（圆环 / 短条 / 图标底），不可作文字或焦点环**。

## 技术说明

**零新增依赖。** 只用 Node 内置模块（`http` / `fs` / `child_process`）+ 项目已有的 `js-yaml` 和 `playwright`。不需要 `npm install` 任何新东西。

**只监听 127.0.0.1。** 不对外网开放，不做鉴权（本机单用户场景）。

**不破坏项目的数据契约。** 界面读写的都是项目原有的文件：`cv.md`、`config/profile.yml`、`portals.yml`、`data/applications.md`、`data/pipeline.md`、`reports/*.md`、`output/*`。改完仍然可以用原来的 AI 命令行工具继续操作，两边看到的是同一份数据。

**写操作有保护：**

- 简历保存前自动备份 `data/cv.backup-<时间戳>.md`
- `config/profile.yml` 落盘前会重新解析一遍，产生非法 YAML 就拒绝保存（原文件不动）
- `portals.yml` 保存前做 YAML 语法校验
- 脚本执行有白名单，只能跑预设的 43 个脚本；新加的脚本一律默认不可执行，必须显式登记
- 带参数脚本的值走正则白名单校验，且不经过 shell

改了样式或布局之后，起好服务再跑一次自检，比人肉点一遍可靠：

```bash
node ui/server.mjs --port 7317            # 一个窗口起服务
node ui/check-ui.mjs                      # 布局自检（5 分辨率 × 9 视图）
node ui/check-ui.mjs --shots              # 附带把截图写到 output/_shots/
node ui/check-prep.mjs                    # 备考建议：解析 / 兜底 / 导出 + 页面全流程（131 条断言，秒级）
node ui/check-eval-parse.mjs              # 初筛解析回归（纯离线，不看服务）
node ui/check-eval-flow.mjs               # 评估页流程与状态机（打桩，秒级）
node ui/check-eval-flow.mjs --live        # 同上但真跑一次初筛（约 40 秒，验接线）
node ui/check-cv-edit.mjs                 # 简历增删排序回归（打桩，不写文件）
node ui/check-delete.mjs                  # 删除台账行 / 报告（会真删一行一报告，跑完还原）
node ui/check-cv-optimize.mjs             # 简历优化：解析 + 面板流程（会真写一次 cv.md，跑完自动还原）
node ui/check-cn-states.mjs               # 国内投递阶段显示回归（打桩，读真实 states.yml）
node ui/gen-shots.mjs                     # 出一套界面截图到 ui/screenshots/（01–14）
node ui/gen-shots.mjs --with-eval         # 再补一张「初筛结果」态（15，多花约 40 秒）
node ui/gen-shots.mjs --with-cv           # 再补一张「简历添加条目」态（16，秒级，不保存数据）
```

退出码 0 全部通过，1 有失败项并逐条列出。

**为什么 `check-eval-flow.mjs` / `check-cv-edit.mjs` 默认打桩：** 拦截接口返回固定数据，
断言就能做得很精确（连 `档位 强匹配` / `结论 通过` 这两个 span 的文本都比对），
而且秒级完成、不烧 AI 额度、不写任何文件。真实 AI 只用于验证「接线没断」，放进 `--live`。

**`check-cv-edit.mjs` 存在的理由：** 接口读写、布局断言、解析回归各测一段，
**就是没人测「点添加之后条目还在不在」**——于是那个 bug 活了下来。
它坏掉的方式还特别安静：push 成功了、控制台干净、页面不报错，只是条目被悄悄覆盖回去。

**`gen-shots.mjs` 的编号严格按顶部导航的顺序**（先 5 个一级栏目，再栏目内各项），改导航之后要重跑，
否则截图集和导航对不上。它按 `NAV_GROUPS` 逐页截图 + 组件画廊 + 移动端两态。
`15`（初筛结果）和 `16`（简历添加条目）是「状态」截图，**编号写死**、
不吃静态页面的序号 —— 否则只跑其中一个 flag 时它会顶替前面的号，两次生成的文件名就对不上了。
`--with-cv` 只改浏览器内存里的草稿、**不点保存**，所以不会动 `cv-form.json` 或 `cv.md`。

> 五个自检脚本都用 `process.exitCode` 而不是 `process.exit()`——
> 管道下 stdout 是异步的，`process.exit()` 会在缓冲区刷出去之前终止进程，
> **报告直接丢掉**（表现为「命令成功了但什么都没打印」）。

## 已知限制

- **不支持自动扫岗的中国平台。** 内置岗位源全是海外招聘系统（Greenhouse / Lever / Ashby / Workday 等），没有牛客、BOSS直聘、应届生、拉勾、猎聘。国内求职请按「使用帮助」页的渠道清单手动找，把 JD 粘到「评估岗位」页。
  - 唯一的例外是「**自动投递**」页（BOSS 直聘，见上文）：它只解决**发打招呼语**这件重复劳动，
    不做抓取、不做筛选、不替你判断值不值得投；**要不要投仍然先跑一份评估报告决定**。
    它需要你先用 `node save-cookies.mjs boss` 保存登录态，且**只应在本机使用**——
    cookie 等同于你的账号凭证，不要把它连同 `data/` 目录一起备份到别处或同步到网盘。
    平台规则会变，选择器也会失效；它遇到安全验证会立即停，不会硬闯。
- **不是多用户服务。** 没有登录、没有权限，不要暴露到公网。
- **岗位评估可以在页面里做，改动简历仍然要命令行。** 「评估岗位」页会主动拉起 AI 完成初筛与完整报告；
  但简历改写、面试准备这类需要来回对话的操作，还是在 AI CLI 里做更合适——页面不适合承载多轮交互。
