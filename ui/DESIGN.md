# career-ops 控制台 · 界面设计规范

适用文件：`ui/index.html`、`ui/style.css`、`ui/app.js`
可交互示例：同目录 `design-system.html`（打开即可看到所有组件与状态）

---

## 一、定位与设计原则

这个界面是**操作台，不是执行者**。AI 负责需要判断力的工作（评估岗位、改写简历），
界面负责「看状态、改数据、跑脚本、导文件」。这条定位决定了全部设计取舍：

| 原则 | 具体含义 |
|---|---|
| **信息优先于装饰** | 每个视觉元素都要有信息职责。没有纯装饰的分割线、图标。**层级靠留白、凸起/凹陷的阴影和字重拉开，不靠大面积填色**——一屏里铺两处渐变就等于两处都在喊"我是重点"，反而没有重点 |
| **状态永远可见** | 用户不该猜「它在干什么」。加载、忙碌、成功、失败、空都要显式表达 |
| **破坏性操作要减速** | 覆盖、删除一类动作必须先确认，且焦点默认落在「取消」上 |
| **数据诚实** | 缺失就是缺失（显示「—」），不要用 0 冒充；不确定的加「仅供参考」 |
| **本机单用户** | 不做登录态、不做多租户。但**仍然必须做无障碍**——键盘可达是效率问题，不只是合规问题 |

**风格基调（2026-09-22 第五版 · 新拟态 + 冷调清透）**：中性冷白画布，元素与背景**同色同材质**，
靠一对双向柔光（暗侧右下 + 亮侧左上）表现出"从背景里挤出来"（凸起）或"压进去"（凹陷）。
**冷松绿 `#2f6b52` 是唯一主色**，琥珀 `#c98a3c` 只做"进行中/待办"的强调。卡片圆角柔和、阴影很轻。
第四版的温暖米白已换成冷白 `#f2f4f6`：米白连阴影一起偏暖，大面积铺开容易显"闷、旧"。
这不是一个"皮肤层"——**形状即状态**（凸 = 可点/当前层级，凹 = 已选中/输入区），
所以第三节之后的每一条几何规则都不可脱离这套语言单独修改。

## 二、设计令牌

所有颜色、间距、圆角、阴影、动效时长**只能取自 `style.css` 的 `:root`**。
新增需求先加令牌再使用，禁止在组件里硬编码色值。

### 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--accent` | `#2f6b52` | 主品牌色（**冷松绿**）：主按钮、链接、选中态、进度、强调短标。作文字 5.7:1，作按钮底配白字 6.3:1 |
| `--accent-hover` / `--accent-press` | `#285c46` / `#214c3a` | 主按钮悬停 / 按下 |
| `--accent-2` | `#6f9e85` | 淡一档的绿，**仅图形**（圆环轨道、装饰短条、图标底）。2.8:1，**禁止当文字用** |
| `--accent-soft` / `--accent-soft-2` | `#dbe8e1` / `#cae0d4` | 选中底色、重点指标卡底、焦点外圈 |
| `--accent-line` | `#b3d0bf` | 浅色分隔 |
| `--accent-tint` | `#e4efe9` | 标识面板底（比 `--accent-soft` 再淡一层） |
| `--accent-glow` | `rgba(47,107,82,.22)` | 主按钮外圈的绿色氛围影 |
| `--grad-brand` / `--grad-brand-2` | `#3a7b5e → #2f6b52` | **同色系**浅渐变，只给主按钮加一点体积感；换纯色也不丢信息 |
| `--amber` / `--amber-ink` | `#c98a3c` / `#835618` | 琥珀强调（进行中 / 待办）：`--amber` 只作填充与图形，**文字一律用 `--amber-ink`**（5.8:1） |
| `--ink` | `#3d4247` | 主文本（冷白底 9.2:1） |
| `--ink-2` | `#575e66` | 次级文本、表格正文（6.0:1） |
| `--ink-3` | `#636b73` | 辅助说明、占位符（4.9:1，AA 下限之上） |
| `--ink-faint` | `#a4acb4` | **仅装饰**（2.1:1，禁止用于任何正文或图标标签） |
| `--bg` / `--bg-2` | `#f2f4f6` / `#eceff2` | 画布（**中性冷白**）/ 次级填充（表头、hover、内嵌底） |
| `--card` | `#f6f8f9` | 卡片面：与画布**同色系**，只亮一档 |
| `--sunken` | `#eceff2` | 凹陷面：输入框、代码块、进度槽 |
| `--line` / `--line-2` / `--line-3` | `#e0e4e9` / `#d6dce3` / `#c4ccd4` | 三级"硬"分隔：表格行线 / 控件边 / hover 边 |
| `--nm-dark` / `--nm-light` | `#d6dce3` / `#ffffff` | **新拟态阴影对**：全站凸起/凹陷都从这两支派生 |
| `--ok-*` / `--warn-*` / `--bad-*` / `--info-*` | 见 CSS | 语义色，成组使用 `bg` + `ink` + `line`（`ink` 均 ≥4.5:1） |

**配色策略（2026-09-22 第五版 · 冷调清透）**：主色沿用新拟态版的绿，但**整体转冷并压深一档**
（`#3f6b4d` → `#2f6b52`），画布从温暖米白换成**中性冷白 `#f2f4f6`**，阴影暗侧同步转冷
（`#d5caba` → `#d6dce3`）。琥珀仍只做"进行中 / 待办"的强调，**不参与大面积铺底**。
层级不再靠描边，而是靠
**「同色材质上的凸起与凹陷」**：卡片、按钮从 `--bg` 冷白画布上"挤"出来（凸），输入框、
进度槽、选中页签压进去（凹）。因此有两支硬性规则：

1. **卡片不许有描边**。1px 边框会立刻戳破"同一种材料"的错觉——边界只由
   `--nm-out`（暗侧 + 亮侧双向阴影）交代。
2. **浅色不许当文字**。新拟态天生爱用接近画布的浅色，那是低对比度的陷阱：
   `--accent-2` / `--amber` / `--ink-faint` 一律只做图形，正文只走 `--ink*` / `--accent` / `--amber-ink`。

**语义色使用规则**：一个提示块内只用一种语义色；`--ok` 只用于「确认成功」，
不要拿绿色表示「普通信息」（那是 `--info`）。

### 度量

| 类别 | 令牌 | 说明 |
|---|---|---|
| 间距 | `--sp-1` … `--sp-8`（4 / 8 / 12 / 16 / 20 / 24 / 32 / 40） | 全为 4 的倍数，禁止写奇数外边距。`--sp-7`(32) 用于段与段，`--sp-5`(20) 用于卡与卡 |
| 圆角 | `--r-xs` `--r-sm` `--r` `--r-lg` `--r-xl` `--r-pill`（6 / 10 / 14 / 20 / 26 / 999） | 比上一版**放大一档**（新拟态是"柔软的实体"，直角会显得硬）：控件 `sm`，内嵌块 `r`/`lg`，卡片与首屏两栏 `xl`，弹层 `lg` |
| 新拟态凸起 | `--nm-out` / `--nm-out-sm` / `--nm-out-xs` | `Npx Npx blur var(--nm-dark), -Npx -Npx blur var(--nm-light)`。卡片 `out`，按钮 `out-xs`，按钮悬停 `out-sm`（**抬得更高**） |
| 新拟态凹陷 | `--nm-in` / `--nm-in-sm` / `--nm-in-lg` | 同两支阴影加 `inset` 反向。输入框 `in-sm`，进度槽 `in`，空状态图标底 `in` |
| 真投影 | `--sh-xs` … `--sh-lg` | 只给**浮在遮罩之上**的层（模态 / toast / 下拉面板）：暖色 `rgba(70,65,58,…)`。新拟态的"挤出"感压在深色遮罩上会糊成一团，反而不像浮层 |
| 字号 | `--fs-xs` 11.5 / `sm` 12.5 / `base` 13.5 / `md` 15 / `lg` 18 / `xl` 22 / `2xl` 28 / `3xl` 32 / `4xl` 44 | 正文基准 `base`；`3xl` 给迷你指标数值，`4xl` **只给一屏里最大的那个数**（首屏是圆环中心） |
| 动效 | `--dur-1` 120ms（hover）/ `--dur-2` 180ms（状态切换）/ `--dur-3` 280ms（进出场） | 缓动统一 `--ease`；弹层入场用 `--ease-out` |
| 布局 | `--nav-h` 64 / `--content-max` 1560 / `--drawer-w` 320 | 改这些就等于改全局布局。**旧的 `--sidebar-w` 已删**（左侧竖栏时代） |

### 字体

- 正文：`--font`（系统 UI 字体栈，含 Microsoft YaHei / PingFang SC）
- 数据与代码：`--mono`。**规则：所有数字型内容用等宽字体**（评分、计数、日期、编号、文件大小），
  这样纵向对比时数位对齐。这类元素加 `.num` 或 `.stat .v` 类即可，不要单独写 `font-family`。

## 三、布局与信息层级

### 顶部导航横栏（5 栏 + 下拉）+ 单列内容区（2026-09-22 第四版）

```
┌──────────────┬──────────────────────────────────────────┬────────────────┐
│ 品牌（方块+名）│ 总览  做简历▾  评岗位▾  分析  系统▾         │ 项目目录胶囊     │ ← `.sidebar` 64px，**粘性、铺满视口宽**
└──────────────┴──────────────────────────────────────────┴────────────────┘
                    ┌──────────────┐
                    │ 编辑简历      │ ← 悬停/聚焦/点开的栏目下方
                    │ 简历工具包    │   浮出 `.nav-menu` 下拉面板
                    └──────────────┘
┌──────────────────────────────────────────────────────────────────────────┐
│ 页面标题行 `.topbar`：标题 + 一句话说明 + 次要操作按钮                        │ ← 随内容滚动，**不粘性**
├──────────────────────────────────────────────────────────────────────────┤
│ 内容区（铺满可用宽度，上限 1560px）                                          │
│  · 状态提示 / 指标卡（「是什么」）                                           │
│  · 数据区（表格、卡片列表）                                                  │
│  · 解释区（说明文字、折叠的原始数据）                                         │
└──────────────────────────────────────────────────────────────────────────┘
```

- **一级只有 5 个栏目**：总览 / 做简历 / 评岗位 / 分析 / 系统。9 个功能项收进下拉面板，
  一级目标数**不再随功能增加而膨胀**；「系统」正好装下那些琐碎入口（求职配置 / 全部脚本 / 使用帮助）。
- **品牌左 / 栏目居中 / 目录右**：居中靠 `.nav { flex: 1; justify-content: center }`。
- **单项栏目不出下拉**：总览、分析点了直接走（head 上是 `data-go`，不带 caret、不带
  `aria-haspopup`）；多项栏目才渲染成下拉触发器。判断依据是分组里的项数，写死在 `renderNav()` 里。
- **选中态是"压下去"**：`.nav-col.is-current > .nav-col-head` 用 `--nm-in-sm` 凹陷 + 绿字。
  这是新拟态里最自然的状态语言——**凹陷 = 你正站在这块地上**。悬停的栏则轻轻凸起（`--nm-out-xs`）。
  抽屉（`<1024px`）里回到"整块浅底 + 左侧竖条"的竖栏惯例。
- **下拉的展开是纯 CSS**：`:hover` / `:focus-within` / `.is-open` 三选一即可展开，
  JS 只做两件事——同步 `aria-expanded`、以及"同时只允许一栏打开 / 点外部和 Esc 收起"。
  **没有新增交互状态机**，抽屉那套（`setDrawer` / `initShell` / `drawerMQ`）一行没动。
- **横栏排不下时按这个顺序让掉装饰**（`style.css` 第 21 段）：>1439 全都要；
  ≤1439 让掉右侧目录胶囊；≤1279 让掉品牌文字（只留方块）；≤1119 让掉栏目图标。
  **绝不允许用 `overflow: hidden` 裁栏目** —— 被裁掉的入口等于不存在，
  `check-ui.mjs` §1b 专门断言「5 个栏目一律 0 个越界」。
  注意 `.nav { overflow: visible }`：下拉面板必须能溢出横栏。

**为什么导航在顶部、且收成 5 栏**：用户给的参考图是横向导航的 dashboard；竖栏在中文字数
不多时会长期占掉 300px 横向空间。改成横条后**横向空间全部还给内容**；再收成 5 栏，
则解决了"功能一多横栏就爆"的长期问题。

**「竖栏 → 横条」是纯 CSS 变形**，这是本版最重要的实现约束：
DOM 与无障碍契约**一字未改**（仍是 `#sidebar` / `#nav` / `#navToggle`、`aria-expanded`、
`body.drawer-open`），只把 `.sidebar` 改成 `display: flex; position: sticky; top: 0;
height: var(--nav-h)`。因此 `app.js` 里的抽屉逻辑（`setDrawer` / `initShell` / `drawerMQ`）
**一行都不用动**，`<1024px` 由媒体查询整体还原成左侧抽屉。
改这一块前先读 `style.css` 第 05 段（顶部导航）与第 21 段（响应式），两处的断点必须一致。

**画布是平的**：没有全局渐变底纹。这一版连"1px 描边划边界"也省掉了 ——
卡片靠**与画布同色 + 双向柔光**从背景里"挤"出来（新拟态的核心手法），
再叠一层渐变底纹只会让凸起感失效。

**宽度策略**：导航条铺满视口宽；内容区**铺满**可用宽度，只在视口宽于内容上限（1560px）后才居中收边
（旧的居中门槛是 1860 = 300 竖栏 + 1560，导航改到顶部后不再占横向空间，门槛随之降到 1560）。**不要**用"大屏居中 + 上限调小"的做法——那会变成屏幕越大两侧空白越多。
超宽屏居中后两侧留白**必然对称**，这是内容上限的代价，不是 bug；`check-ui.mjs` §1b 断言的是
「左右留白相等」，不是「单侧 ≤96px」（后者是竖栏时代的阈值，在超宽屏必然假红）。

**每个视图的阅读顺序固定为三段**：先给结论（状态/指标），再给数据（表格/列表），
最后给解释（hint、details 里的原文）。新增视图必须遵守这个顺序。

### 总览页的两栏版面（`.ov-*`，style.css 第 25 段）

总览页是唯一一个「既要引导新手、又要展示数据、还要报环境状态」的视图。
第一版是五张同级卡片平铺（开始使用 / 初始化状态 / 4 个指标 / 转化漏斗 / 环境检查），
全都白底、同内边距、同字重 —— 结果新用户第一眼分不清「要做什么」和「看什么数据」，
主行动按钮也淹没在卡片里。第二版折成三段纵向分层，第三版按模板重排为首屏两栏：

| 位置 | 容器 | 视觉权重 | 内容 |
|---|---|---|---|
| ① 左栏 | `.ov-hero-main` + `.ov-tint` + `.ov-steps` | 最高：凸起卡 `--nm-out`，顶部一块**凹陷** `--accent-tint` 标识面板 | 一句话定位 + 两步流程；**全页唯一的 `.primary` 在这里** |
| ① 右栏 | `.ov-hero-side` + `.ov-ring` + `.ov-stats` | 同高：凸起卡 `--nm-out` | 简历完整度圆环 + 4 枚迷你指标（2×2，指标块是**凹槽** `--nm-in-sm`） |
| ② 数据概览 | `.ov-card` + `.ov-stats` + `.ov-funnel` | 中：凸起卡 `--nm-out-sm` | 转化漏斗四级改成四张并列迷你卡 |
| ③ 环境状态 | `.ov-env` | 最低：比画布深一档的**平底**、**不凸不凹**（`box-shadow: none`） | 一句话结论 + 点状轻标签 |

首屏栅格是 `minmax(0, 1.12fr) minmax(0, 1fr)`：左栏装「要做什么」（说明 + 按钮，内容更宽），
右栏装「现在什么水平」（圆环 + 小指标，天然更窄）。`<1200px` 落回单栏，**右栏排到左栏下面**
（先看要做什么，再看现在什么水平，顺序不能反）。

七条硬规则，改这一页时必须守住：

1. **一屏只有一个 `.primary`**，且必须落在①左栏里。因此总览页的**标题行不放 primary**
   （两处 primary 互相削弱，谁都不显眼）。标题行入口一个都不少，只是降级成次级按钮。
2. **当前该做的那一步**才拿 `.primary` + `.btn.lg`：简历没填完时是第 1 步，
   填完了才轮到第 2 步。另一步退成 `.is-todo`（虚线 + 透明底）。
3. **首屏只有一个"最大的数"**：它现在是圆环中心的完整度（`--fs-4xl`），
   迷你指标退到 `--fs-3xl`。一屏里两个 44px 的数字等于没有重点。
4. **数值大于标签**：`.ov-stat > .v` 用 `--fs-3xl`（`.is-hero` 用 `--fs-4xl`），
   而 `.k` 固定 `--fs-sm`；比例不低于 2.5 倍。
5. **圆环的 `stroke-dasharray` 必须两段非负数**。完整度 100% 时
   `2πr - round(2πr)` 会算出 `-0.0`，而 SVG 不接受负值 —— 整条 dasharray 会被判无效，
   圆环退化成"没设虚线"的一整圈。代码里用 `Math.max(0, …)` 夹住
   （`check-overview.mjs` A2 有对应断言）。
6. **环境标签是点状轻标签**（`.ov-chip`）：无边框、无底色，状态全靠一枚 6px 圆点
   （绿=`--ok-dot` / 橙=`--warn-dot` / 灰=纯计数）。**不要改回带边框的 `.badge` 平铺**
   —— 十几枚 pill 排在一起就是「标签墙」，正是这一页最初的毛病之一。
7. 业务字段与 class 契约（`.ov-step` / `.ov-stat` / `.ov-fn` / `.ov-chip` / `.ov-env`）
   **一个都不能改**：`check-overview.mjs` 的 B 段是按这些名字逐条数业务内容的。

回归：`node ui/check-overview.mjs`（首屏栏数、圆环合法性、栅格列数、唯一 primary、
字号比例、标签色温、五档断点、未就绪分支，以及「改版没删业务字段」的文案清单）。

### 面试备考建议页：三段式纵列（`.prep-*`，style.css 第 26 段）

这一页的输出天然是**三层递进**（先补什么 → 拿什么项目证明 → 去哪学），所以不是
「一张大表 + 若干卡片」，而是**三张卡纵向排开，卡内是「条」不是表格**：

- **为什么不用表格**：每条知识点有 2–4 个字段（名称 / 优先级 / 掌握程度 / 为什么缺），
  项目有 5 个（名称 / 目标 / 技术要点 / 价值 / 工作量）。表格在窄屏必然横滚，
  而定义列表（`.prep-dl`）能自己折行 —— 「对岗位的价值」这种长标签不会把正文挤成一列字。
- **`.prep-dl` 是两列栅格**（`6.5em minmax(0,1fr)`），`<520px` 落成单列。
  标签列宽度写死 `6.5em`：换成 `auto` 会让每条的标签列宽度不一致，纵向读下来是锯齿。
- **条与条之间只用一条极淡的分隔线**（`.prep-item` 的 `border-top: 1px solid var(--line)`），
  不给每一条单独套卡片 —— 二十几条各自成卡，纵向会长到没法看。
- **待选项（`数据不足`）在下拉里灰着但看得见**，选项文字后加「— 数据不足」，
  选中时工具条下方现场写明原因，生成按钮同时置灰。**不要**让人选完再弹一个错。

顶部的选择行（`.prep-pick-row`）`align-items: flex-end` 是必须的：`label` 上面有一行
「备考哪个岗位 / 生成方式」的说明文字，不对齐底边的话按钮会被顶下去一行，三个控件不在
同一条基线上。`<768px` 三个控件各自占满一行。

**五项状态都要有表达**（照第五节的总规范）：列表拉不到 → 可重试的错误态；一份报告都没有
→ 空状态 + 「去评估岗位」出口；`cv.md` 为空 → 工具条下的全局提示（不是等点了才弹）；
生成中 → 骨架 + 「通常几十秒到几分钟」；数据不足 → 清单式说明缺哪一样。

### 长任务（AI 评估）的交互规范

`/api/eval` 是唯一会跑几十秒到几十分钟的操作，**它的反馈设计比普通表单重要得多**。

**先说为什么分两阶段：** 完整评估要读约 17.6 万字符规则 + 写 A–H 报告 + 更新台账，
实测超过十分钟。把它做成一次点击，用户点完盯着转圈十分钟，中途必然想刷新。
所以拆成「初筛（约 30 秒，给分数）」+「完整报告（可选，很慢）」两步。

**四段式反馈，缺一不可：**

| 阶段 | 表现 |
|---|---|
| 等待 | 卡片内 `#evHint` 用 `spinner` + 文案说明耗时（初筛「半分钟内」/ 完整「十分钟以上」），同时把日志区展开显示已提交的内容 |
| 进行中 | 日志区 `#evLog` 显示服务端返回的原始输出；状态徽标 `badge warn` = 「AI 初筛中」/「AI 写报告中」 |
| 成功 | 徽标转 `badge ok`；**用服务端解析好的结构化字段**渲染结论条；初筛后按分数决定「生成完整报告」按钮显隐 |
| 失败 | 徽标转 `badge bad`；**必须说清「发生了什么 + 怎么办」**，不能只丢原始报错 |

**为什么要把分数提取出来做成结论条：** AI 输出是几百行长文，
用户点完按钮最想知道的就是「几分、投不投」。服务端解析出 `score` 后与门槛
（取自 `/api/ai-status`）比对，直接给出三档结论：

- `≥ 4.0` → `notice ok`「值得投递」
- `≥ 门槛(3.0)` → `notice warn`「过了门槛，属补投位」
- `< 门槛` → `notice bad`「低于门槛，不建议投」

**解析放服务端，不放前端。** 前端只渲染 `r.triage.{score,verdict,tier,why}`，
不再自己写正则——标签中英混杂（`分数/评分`、`结论/判定`、`评级/分级/档位`、
`原因/理由/评估理由`），规则集中在一处才好维护。

**按钮的「档位」是有逻辑的，不是装饰：**
初筛分数 `< 门槛` 时把「生成完整报告」从主按钮**降级为次按钮**（`primary` → `ghost`），
文案改成「仍要生成完整报告」并说明「除非有保底、地域刚需等理由」。
刻意**不隐藏**——低分岗位也可能有特殊理由，把路堵死不对；
但也不该用主按钮诱导用户对着低分岗位白等几分钟。
分数没解析出来时按主按钮处理（信息不足，不替用户做决定）。

**文案与按钮态度必须一致。** 反例（已修）：按钮被隐藏了，文案却写「也可以点上面的按钮」。

**完整评估跑完**则反过来：隐藏自己、露出「查看报告」，并把 `#evNextHint`
换成「报告已写进 `reports/`，台账也按结论更新过了」。

**三个失败分支要区分开（都是实际踩过的坑）：**

- **超时**：提示「评估可能仍在后台跑完」——因为服务端 timeout 比页面 timeout 长，
  让用户去「评估报告」看看，而不是让他立刻重跑一遍（白花钱）。
- **空返回**：CLI 端口冲突或未登录时会静默返回空字符串。服务端识别后给出具体指引
  （换端口 / 去登录 / 稍等重试），**不要把空字符串原样展示**——用户只会以为是坏的。
- **假成功**（最难缠的一种）：有输出、退出码 0，但报告根本没写出来。
  原因是无头模式写权限被拦，AI 会礼貌地回一段「我写不了文件」再加完整结论。
  如果只按「有输出就是成功」判定，页面会显示成功而 `reports/` 空空如也。
  **判定标准要落在产物上，不是 AI 的自述**：服务端前后快照 `reports/` 目录，
  比对 mtime 判断文件是否真的新增/被重写，没落盘就把 `ok` 置 false。

**幂等与缓存：** 评估成功后 `S.tracker = S.stats = null`，
让其他页面重新拉取。评估会同时改 `reports/` 和台账，只清一个是错的。

**「再评估一个」必须复位到干净状态**，包括 `triageScore` 和被隐藏的按钮——
否则上一个岗位的分数会漏到下一个岗位的结果里。

### 工具面板（两个入口共用一个组件）

「全部脚本」「简历工具」两页复用同一个 `renderToolPanel(view, scripts, filterGroups)`，
差别只在 `filterGroups`：`null` 全部、`['cv']`。

**为什么要合并：** 同一份脚本目录在两个场景下出现，如果各写一套渲染，
就会出现"A 页有参数校验、B 页没有"这类不一致。共用组件保证两处行为永远同步。
（原先是三个入口，第三个「数据洞察」已随该页整体下线。）

**参数表单的规则：**

- 只有声明了 `params` 的脚本才展开表单，其余的保持紧凑卡片（一行 desc + 一个「运行」）。
- 带参数的卡片加 `.has-params`，`grid-column: 1 / -1` 独占整行——**不要让表单挤在 240px 的窄列里**。
- 参数区用 `.param-grid`（`auto-fit, minmax(230px, 1fr)`）自动分列；
  `multi: true` 的参数（如一批岗位链接）加 `.wide` 独占一行。
- 必填项在 label 后跟一个 `.req` 星号，**不要用红色徽标**——表单里满屏红徽标会破坏视觉节奏。
- 校验失败给输入框加 `.field-bad`（红边 + 红底），**同时**把原因写进 `#toolLog` 和 `#logHint`。
  只变色不说话，用户不知道为什么被拒。
- 参数值经 `pattern` 正则校验后作为 `spawn` 的**数组元素**传入。
  **任何情况下都不要拼字符串交给 shell。**

### 标题行 `.topbar`

- 它是**画布上的一行**，不是卡片，也**不粘性**（随内容滚走；只有顶部导航横栏常驻）。
- 左起：汉堡按钮（仅 <1024px）→ 页面标题 `h1` → 一句话说明 → 弹性空位 → 次要操作按钮组。
- **标题行只放次级动作**：同一时刻最多一个 `.btn.primary`，而那个 primary 属于页面正文里的
  主行动（如总览页首屏的「评估一个岗位」）。两处 primary 互相削弱，反而谁都不显眼。
- 标题下的说明用 `.sub`，竖线分隔；窄屏（<768px）自动隐藏。

## 四、组件规范

### 按钮 `.btn`

四种变体：默认（次级动作）、`.primary`（每屏最多一个）、`.ghost`（图标按钮、取消）、
`.danger`（破坏性）。

`.primary` 是**冷松绿实心**（`--accent` 上的同色系浅渐变），不加跨色相渐变、不加彩色光晕 ——
白字压在上面的对比度是 6.14:1，过 AA。次级按钮是**与画布同色的凸起**（无描边），
主次靠"有没有绿底"一眼区分。**所有按钮都不给 `border`**：形状完全由 `--nm-out-*` 交代。

**必须有四种状态**：

| 状态 | 表现 |
|---|---|
| hover | 抬得更高（`--nm-out-xs` → `--nm-out-sm`）；`.ghost` 转 `--bg-2` |
| active | 下沉 1px + **翻成凹陷**（`--nm-in-sm`）（"按进去"的手感） |
| focus-visible | 2px `--accent` 焦点环，偏移 2px。**鼠标点击不出现，键盘操作才出现**。（不用 `--accent-2`：#6f9e85 只有 2.8:1，过不了 WCAG 非文本 3:1） |
| disabled / busy | 透明度 .55 且 `cursor: not-allowed`；busy 时保留原宽度并换成转圈 + 文案 |

**忙碌态一律用 `busy(btn, true, '文案')`**，不要手写 `innerHTML`——它会记住原始内容并在
`busy(btn, false)` 时还原，避免按钮宽度跳动。成功后通常直接 `route()` 重绘，可不复原。

### 表单

- 每个控件都要有可见 `<label>`（`.field > span`）；纯视觉隐藏的用 `.sr-only` + `for`。
- 必填项在 label 后加 `<span class="req">*</span>`。
- **校验反馈就地显示**：`setFieldError(input, msg)` 会加 `.is-invalid`、插入 `.field-error`
  并设 `aria-describedby`。不要只用 toast —— 提示条会消失，用户回来时不知道哪里错了。
- 校验时机：提交时。失焦即校验只在字段格式明确（如 URL）时使用。

### 卡片 `.card`

- 标题用 `<h2>` 或 `.card-head > .card-title`，两者都会自动带 3px 品牌色短标。
- 可点击的卡片：加 `.is-clickable` **并且** `role="button"` + `tabindex="0"` + `aria-label`，
  同时绑定 Enter / Space —— 声明成按钮就必须能用键盘触发。
- 卡片内最后一个元素不产生多余外边距（已在 CSS 里统一处理）。
- 圆角 `--r-xl`(20)、**与画布同色**（`--card`）、**零描边**、阴影 `--nm-out`（暗侧 + 亮侧双向）。
  **卡片从冷白画布上"挤"出来靠的就是这对阴影** —— 一旦加上 1px 描边，"同一块材料"的错觉
  立刻破功；一旦换成单方向投影，它就从"凸起"变成"贴纸"。悬停时换成更大的 `--nm-out`。
- 卡片间距 `--sp-5`(20px)，段与段之间 `--sp-7`(32px) —— 段间距必须明显大于卡间距，
  否则一页卡片会糊成一整块。

### 工具条 `.toolbar` / 分栏 `.split` / 报告栅格 `#rList`（2026-09-22 新增）

三样都是「把散在画布上的元素收进一个容器」，解决同一类问题：

| 组件 | 用在哪 | 解决什么 |
|---|---|---|
| `.toolbar` | 评估报告、面试备考建议的搜索 / 筛选 / 计数 | 原来是一行裸控件摊在画布上，浮在卡片外面没有归属感，跟下面的列表也拉不开从属关系。收进一张卡后它就是「这张列表的头」 |
| `.split` | 评估岗位页（左＝JD 输入 / 右＝引擎卡 + 进度 + 后续动作） | 原来自上而下堆四张卡，点完按钮结果出现在屏幕下方，还要往下滚才看得到。`minmax(0, 1.15fr) minmax(0, 1fr)`，`<1200px` 落单列 |
| `#rList` | 评估报告列表 | 一列排下来宽屏每行只用一个入口，横向空间全浪费。改 `repeat(auto-fill, minmax(330px, 1fr))` 卡片栅格 |

工具条的窄屏规则：`flex-wrap: wrap` + 控件各自 `flex: 1 1 100%`，
**半截输入框在手机上没法用**（`check-ui.mjs` §1c 断言窄屏必须分两行）。

### 表格

- 外层必须有 `.table-wrap`（`overflow-x: auto`），否则窄屏会撑破页面。
- `<thead>` 粘性置顶，配 `.sr-only` 的 `<caption>` 说明表格内容。
- 数字列用 `td.num`（等宽 + `--ink-3`），操作列用 `td.act`。
- 空结果不要留空白表格：在 `<td colspan>` 里放空状态组件，并给「清空筛选」的出口。

### 报告正文 `.md` / `.md-report`（2026-09-23 新增 `.md-report`）

`.md` 是 Markdown 渲染容器（报告详情、简历版本预览、求职信结果共用），默认
`max-width: 78ch`。**侧栏里的预览**（简历版本、求职信结果）沿用这个值 —— 它本来就窄。

**报告详情页必须再加 `.md-report`**，因为报告正文在宽屏下被 78ch 锁死过一段：
1440 视口下卡片 1392px、正文只有 618px，**右侧空出 774px**，而 A) 那颗五列表格
又被压在 618px 里逐字换行。`.md-report` 做两件事：

| 规则 | 效果 |
|---|---|
| `max-width: none`，正文块铺满卡片 | 右侧空白 774px → 40px |
| `> p / > ul / > ol / > blockquote` 限 `96ch` | 跑文仍保持可读行宽（中文约 58 字/行），**不是**让每行拖到 1300px |
| `≥1100px` 时 `table { display: table; width: 100% }` | 表格吃满可用宽度 —— 表格是这份报告里最需要横向空间的东西 |
| `<1100px` | 落回 `.md table` 原来的 `display: block` + 自身横向滚动兜底 |

小节标题、`<hr>` 与表格同宽（都是铺满），只有**跑文**收在 96ch —— 于是每一节
读起来是「全宽的分节块 + 一条行宽可控的正文」。**别把 `p` 的限制也套到 `table` 上**：
那等于又退回 618px 的窄表格。

### 提示条 `.notice` / 徽标 `.badge` / 轻提示 `.toast`

- `.notice` 用于**常驻**说明（警告、须知），四色对应 ok / warn / bad / info。
  它是块级容器，**不要求包裹元素**，但需要图标时用 `.notice-ico`（浮动排列）。
- `.badge` 用于短状态词（状态、评分、计数）。评分徽标的颜色规则：
  **≥4 绿 / ≥3 黄 / <3 红**，且必须带 `/5` 单位。
- `.toast` 用于**动作结果**的一次性反馈，3.2 秒自动消失（错误 8 秒），可手动关闭，
  最多同时 4 条。容器 `#toast` 带 `role="status" aria-live="polite"`，读屏会自动播报。

## 五、交互反馈规范

### 五种状态必须有明确表达

| 状态 | 组件 | 要求 |
|---|---|---|
| **加载中** | 骨架屏 `.skeleton` | 形状要接近真实内容（`viewSkeleton(id)` 按视图给不同骨架），同时 `#view` 设 `aria-busy="true"`。**不要只放一句「正在读取」** |
| **悬停** | 阴影加深/抬高（凸起变大）、底色微调，120–180ms | 必须能看出「这里可以点」。纯触屏设备（`hover: none`）不做抬高位移，避免状态粘住 |
| **点击** | 下沉 1px + 下沉色 | 立刻有反馈，不等接口返回 |
| **错误** | `.notice.bad` 或错误态组件 | 错误要**留在页面上**（含重试按钮），而不是只弹一次 toast。错误文案必须说清「发生了什么 + 怎么办」 |
| **空状态** | `emptyState()` | 三要素：图标 + 标题 + 说明，**并且给下一步的出口**（如「添加待评估岗位」）。只有「暂无数据」四个字是禁止的 |

### 长任务（PDF 生成、脚本执行）

1. 点按钮 → 按钮立即进入忙碌态；
2. 同步输出滚动日志（`role="status" aria-live="polite"`），让用户看到进度；
3. 接口超时要区分对待：普通请求 90 秒，PDF 300 秒，脚本 600 秒（`api(path, { timeout })`）。

### 文案语气

- 用第二人称、说清后果，不用「操作失败」这种无信息量的话。
  反例：`保存失败` → 正例：`保存失败 / 配置文件写坏会让所有评估静默出错，已拒绝写入，原文件未改动。`
- 危险动作的确认按钮写动作本身（「覆盖表单」），不要写「确定」。
- 数字与单位之间留空格，中文与英文之间留空格。

### 动效

- 时长只用 `--dur-1/2/3`；位移不超过 10px；不做无限循环动画（骨架屏的流光除外）。
- 必须响应 `prefers-reduced-motion: reduce`：所有动画时长压到 0.001ms，去掉位移。

## 八、一致性与可维护性约束

### 命名约定

- CSS：组件用语义类（`.card`、`.badge`、`.empty`），状态用 `is-` 前缀（`.is-busy`、`.is-invalid`、`.is-clickable`）。
- 颜色/尺寸：只用令牌变量，出现字面量色值即视为缺陷。
- JS：DOM 查询用 `$` / `$$`；HTML 拼接一律先 `esc()`（报告、公司名、JD 都来自外部，属不可信内容）。

### 新增一个视图的接入步骤

1. 在 `NAV_GROUPS` 里决定归属分组（不要新建分组，除非确实超出五个阶段的语义）；
2. 在 `TITLES` 里补 `[标题, 一句话说明]`；
3. 写 `VIEWS.<id> = async function (view) {...}`；
4. 在 `viewSkeleton()` 里给这个视图一个形态接近的骨架（默认值是长文本骨架）；
5. 状态处理齐三件套：加载用骨架（框架已代劳）、**空用 `emptyState()` 且给出口**、
   错误交给 `route()` 的 `errorState()`（也可在视图内单独处理，如 `openReport`）；
6. 写操作按钮用 `busy()`；破坏性操作用 `confirmDialog({ danger: true })`；
7. 表格包 `.table-wrap` + `.sr-only` caption；纯数字列用 `.num`；
8. 最后按第六、七节逐条自查无障碍与断点表现。

**如果是"再开一个工具面板"这类视图，别重写渲染逻辑**——直接三行：

```js
VIEWS.<id> = async function (view) {
  const scripts = await api('/api/scripts');
  S.scripts = scripts;
  renderToolPanel(view, scripts, ['<脚本分组>']);   // null = 全部
};
```

同时要改三处，否则回归自检会漏测：

- `ui/check-ui.mjs` 的 `VIEWS` 数组（分辨率×视图遍历用）
- 该文件里的 `a11y.cols` / `a11y.navCount` 期望值（一级 5 栏 / 功能项 10 个）
- `ui/check-cn-states.mjs` 里的 `navCount` 期望值（同一件事有两处断言，别只改一处）
- `ui/gen-shots.mjs` 的 `PAGES` 数组（新页面追加在**末尾**，插在中间会把已有截图的编号顶掉）
- 本文件与 `README.md` 的导航结构表

**如果这个视图有自己的解析 / 兜底逻辑，再补一个专用自检**（先例：`check-prep.mjs`）。
判断标准是「坏掉时会不会静默」——「面试备考建议」的解析坏掉时页面照常出、控制台干净，
只是三条建议全变成空话，这种就必须有断言钉住。新自检脚本建议**分两段**：
纯函数段（直接喂真实数据与仿真输出，不开浏览器、不联网、不依赖 Ollama）+
页面段（真点一遍全流程）。这样失败时一眼能看出是「算法坏了」还是「接线断了」。

### 加一个可执行脚本

在 `server.mjs` 的 `SCRIPTS` 里登记：

```js
脚本键: {
  args: ['xxx.mjs'],            // 固定参数，写成字面量
  label: '中文名', group: 'diagnose',
  desc: '一句话说明', slow: true,          // slow → 超时放宽到 10 分钟
  params: [{                     // 需要页面传参时才写
    name: 'q', label: '搜索关键词', type: 'text',
    required: true, hint: '占位提示',
    pattern: '^[\\w\\-]{1,80}$', // 必须写！这是防注入的唯一防线
  }],
}
```

- `flag: '--url'` → 传成 `--url <值>`；留空 → 作为位置参数追加。
- `multi: true` → 按空白拆成多个位置参数。
- `pattern` 用 `^...$` 全串匹配，只放行该参数**真正需要的字符**；
  宁可严一点让用户改输入，也不要放行 `;` `|` `$` 这类字符。
- 加完在页面上点一次「运行」确认；值经 `spawn` 数组传入，不经 shell。

### 表单的状态归属（一条硬性规则）

**编辑器类表单一旦被用户改过，服务端返回的数据就不能再覆盖它。**

简历编辑器（`VIEWS.cv`）踩过这个坑，值得记下来：

```js
// 错：rerender() 里重新拉一次 /api/cv 再整体覆盖
async function rerender() {
  const again = await api('/api/cv');
  Object.keys(CV_SCHEMA).forEach((k) => { form2[k] = again.form[k]; });   // ← 覆盖
  route();
}
```

后果有两层，第二层比第一层严重得多：

1. 点「+ 添加证书」→ 新条目 `push` 进数组 → 覆盖 → 数组回到空 → **条目当场消失**。
   表现是「点了添加没反应」，控制台干净、不报错，只能靠肉眼发现。
2. 同一个覆盖会**把用户已经敲进表单的所有文字一起冲掉** ——
   只要点一次上移 / 下移 / 删除就触发。用户会认为是「白填了」。

**规则：** 每个编辑器维护一份草稿（`S.cvDraft`）+ 一个脏标记（`S.cvDirty`）。
服务端数据只用于「首次载入」和「没有改动时」，有改动后一律以草稿为准。

**配套要求：**

| 要求 | 理由 |
|---|---|
| 结构操作后本地重画，不重新拉服务端 | 拉回来就会覆盖，这是 bug 的根源 |
| 重画时保留滚动位置（`route({ keepScroll: true })`） | 「+ 添加」按钮在页面下方，滚回顶部会被当成「没反应」 |
| 派生指标（如完整度）交给服务端算（只读接口） | 规则只留一处。前端抄一份，改了权重两处就会分叉 |
| 改过就在 UI 上标出来（按钮文案 / 徽标） | 用户得知道「要保存」，否则关掉浏览器就没了 |
| 关页面用 `beforeunload` 拦；**页内切换不拦** | 草稿在内存里跨视图存活，拦页内跳转只是骚扰 |

**反例：** 曾经在「没有缺失项」的分支里把百分比写死成 `'简历完整度 100%'`。
当前算法下 `缺失为空 ⟺ 100%` 所以碰巧不出错——但这是把百分比规则抄了第二份。
只要是能从数据算出来的东西，就别在展示层再写一遍常量。

### 视图状态必须放会话，DOM 只是投影（一条硬性规则）

`route()` 切页时会重建整个视图（`view.innerHTML = viewSkeleton(id)`），所以**任何只存在 DOM 里的状态都会在切页时消失**。两条硬性要求：

1. **跨页要保留的状态必须挂在 `S` 上**（表单草稿 `S.cvDraft`、评估会话 `S.evalSession`），并提供一个 `paint*()` 函数作为「会话 → DOM」的**唯一**出口；该函数遇到「当前不在这个视图」时直接返回，不得抛错。
2. **异步回调只准写会话，不准写 DOM。** 长任务（评估 4–10 分钟）跑完时，用户很可能已经在别的页面上了，直接 `$('#xxx').textContent = ...` 会命中 `null`。配合「代次」（`runId`）判定：用户 reset 之后回来的旧结果必须丢弃。

**反例（一次真实回归）：** 评估结果直接渲染进 `#evResult`——切去别的页再回来，分数与结论全空；请求飞行中切走还会抛 `Cannot set properties of null`。修法见 `ui/app.js` 的「评估会话」一节，测试见 `ui/check-eval-flow.mjs` 第 8–10 步。「面试备考建议」页照同一套路做（`S.prep` + `paintPrep()` + `runId`）——生成一次要等 AI 跑完，切页回来要是空的，用户会以为白等了一场。

**推论：视图里用 `innerHTML` 恢复出来的按钮，事件必须用委托。** 逐次 `addEventListener` 在重建后失效（评估结果里的报告按钮就踩过这个），委托绑在容器上才跟得住。

### 显示名与存储值分离（一条硬性规则）

**界面上可以显示中文，写回文件必须是规范值。**

投递状态是个具体例子（见 `ui/README.md` 的「国内求职阶段」一节）：

| 层 | 用什么 |
|---|---|
| 界面（下拉文字、徽标、筛选、弹窗「当前」） | `cn` 中文显示名 |
| `data/applications.md` 的 Status 列 | `label` 规范英文值 |
| 发给 `/api/tracker/status` 的 `state` | `id` |

规则本身比这个例子更一般：**任何由后端当"枚举"校验的字段，
前端都只能显示它的友好名，不能把友好名当值传回去。**
`verify-pipeline.mjs` 会校验台账里的状态都是规范状态，
`normalize-statuses.mjs` 会按状态表归一化 ——
一旦中文被写进文件，这两处会报错或静默改写数据。
中文别名（`初试` / `简历筛选` / `谈薪`）只是「人手工写错了也能救回来」的兜底，
不是允许前端写中文的理由。

回归测试 `ui/check-cn-states.mjs` 就是钉这一条的：
它既断言界面显示中文，也断言 select 的 `value` 与请求体里是英文 id。

### cv.md 的「解析 ↔ 重建」契约（一条硬性规则）

**`cvToMarkdown` 是全量重建，所以凡是没有被解析进表单的内容，保存一次就没了。**

链路是这样的：

```
cv.md ──markdownToCv──▶ 表单 ──用户编辑──▶ cvToMarkdown ──▶ cv.md
```

中间没有「原样保留」的旁路。于是只要 `markdownToCv` 读不懂文件里的某种写法，
那一节在表单里就是空的，用户一按保存，它就从 `cv.md` 里**永久消失**，
而且不报任何错。

2026-09-18 真丢过一次：AI 优化把 `## 实习经历` / `## 荣誉奖项` 当成新章节名
（别名表里没有），又把教育背景写成没有 `###` 的裸行 —— 表单里三节全空，
用户看到的是「优化把我填的信息都删了」。

因此定三条：

1. **别名表要穷举，并留兜底。** `SECTION_ALIASES` 收常见中英文叫法，
   `sectionKeyOf()` 还会剥掉「情况 / 经历 / 清单」这类后缀再查一次。
   加新章节名时要连回归一起加。
2. **能降级就别丢。** 没有 `###` 小标题、整节只有列表项，都要能解析出来。
   结构退化成什么样都好说，**一个字都不能少**。
3. **拿不准就报错，不要沉默。** `auditCvMarkdown()` 负责回答
   「文件里有内容、表单里却是空的」是哪几节；两处写盘都拿它当门禁：
   - `/api/cv`（表单保存）：会整节消失 → 409 + 清单，前端 `saveCvForm()`
     弹确认框，用户点了「仍然保存」才带 `force: true` 重发。
   - `/api/cv/optimize/apply`（写回改写稿）：改写稿里解析不出条目的章节 →
     422 且**一个字节都不写**。

两个入口共用 `saveCvForm()`：只在「保存」按钮上做确认、让「导出 PDF」的
自动保存直接写盘的话，用户会在导出的名义下丢掉半个简历。

回归钉在 `ui/check-cv-optimize.mjs` 的 A2 段（解析）与 B6/B7（流程）。

### 删除必须可恢复，且必须说清连带影响（一条硬性规则）

界面上任何「删除」都遵守两条：

1. **先落地，再消失。** 不真删，一律移动或快照到 `data/trash/`：
   报告本体整个搬过去；台账因为「行是文件的一部分」搬不动，就快照整份文件。
   反过来做（先删再备份、或者只删不备份）等于把误点的代价转嫁给用户 ——
   而这套界面的数据全是用户一条条喂进去的，丢了没法再生。
2. **确认框要点名后果，不能只说「确定删除吗」。** 删报告会连带删掉台账里
   引用它的行，就必须逐行写出来（`第7行 华为…`）。用户看不见的连带改动
   和自己点的那个删除是两件事，前者是静默的数据损失。

配套的三条实现约束：

- **台账的增删改都走官方脚本**（`tracker.mjs delete --num N`），它带跨进程锁、
  原子替换和索引重建。自己在 `server.mjs` 里用正则删表行，迟早把表格写坏。
- **报告文件名白名单只写一份**（`REPORT_NAME_RE`），读取与删除共用。两处
  各写一份正则，就会出现「读得到但删不掉」这种谁也想不到的错位。
- **卡片上的删除按钮要拦住冒泡**（`stopPropagation()`）：卡片整体是「打开报告」，
  不拦就变成「点删除＝打开报告」。卡片的键盘处理器还要加 `e.target !== el`，
  否则焦点在删除按钮上按 Enter，删除和打开会同时发生。

回归钉在 `ui/check-delete.mjs`（A 参数校验 / B 真删台账行 / C 真删报告 /
D 前端打桩流程）。B、C 会临时往台账追加自检行，`finally` 里必须还原。

### 禁止事项

- ❌ 在视图里直接写 `fetch`（必须走 `api()`，否则没有超时与统一错误文案）
- ❌ 用 `innerHTML` 拼接未转义的外部数据
- ❌ 自己实现弹层（用 `wireModal` / `confirmDialog`）
- ❌ 用原生 `alert` / `confirm` / `prompt`（阻塞主线程、无法无障碍适配、样式不统一）
- ❌ 用一次性 toast 代替需要留存的错误信息
- ❌ 真删文件（必须先进 `data/trash/`；见「删除必须可恢复」）
- ❌ 空状态只写「暂无数据」
- ❌ 出现横向滚动的页面
- ❌ 给交互元素去掉焦点样式而不补替代方案
- ❌ 重画时用服务端数据覆盖用户已改动的表单（见上一条）
- ❌ 在展示层重算一遍后端已经算好的派生指标
- ❌ 把中文显示名当作枚举值写回文件或传给后端（见上一条）
- ❌ 把「给人看的名字」硬编码在视图里（它属于数据层，例如 `states.yml` 的 `cn`）
